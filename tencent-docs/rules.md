# 騰訊文件內容編輯與交付規範草案

本文件待確認，共同品質引用根目錄 shared-rules.md，文件形式、協作與交付依當次任務。

## 內容與修訂

主要適用於文字文件的撰寫、整理、修訂及交付。表格、簡報、表單等類型需相應流程與驗證，不因同屬騰訊文件就宣稱既有工具支援。

預設自然、清楚的繁體中文，語氣中肯、謙遜、專業。文章、方案、記錄與說明按用途組織，不一律改成社交貼文或微信排版。

先明確用途、讀者、來源與修改範圍，提供完整內容，結論、依據及條件容易查找。標題準確具體，章節、段落、條列、表格與圖示服務內容，不固定開頭與結尾模板。

數字、引文、版本、名稱與結論可追溯；來源、推論與觀察分開，翻譯保留原意與條件。修改已有文件時保留已確認內容與必要結構，局部調整不順便重寫全文，不靜默刪除有意義資訊。決議、責任人、待辦及日期依提供資料填寫，不猜測。

## 排版與交付

使用編輯器可維持的標題層級、段落與表格。長連結、代碼與表格保持可讀，不依賴特殊網頁效果。圖片與圖表解釋內容，保留圖說、來源、單位與限制；生成圖不冒充官方畫面或實際證據。外部素材保留來源及必要使用條件。文件封面按用途，普通工作文件不強制加封面。

提供清楚題目與完整正文，本地稿件與雲端文件的交付狀態分開說明。

需要保存、轉交、含素材或多格式輸出的任務，交付完整 Markdown、相對路徑圖片、來源與說明，以及保留目錄結構的 ZIP。只要求雲端局部修改時不強行另建匯出包。其他格式依需求與實際匯出能力提供，本地 Markdown 或 HTML 存在不代表平台已導入。

多格式保留相同核心內容、圖說與來源；不能維持的格式差異說清楚，不靜默丟失圖片或表格。不強制微信複製 HTML；另做複製或預覽頁時，題目、正文與操作提示分開且版本一致。

## 雲端操作與驗收

新建、寫入或修改雲端文件前，核對當次指示授權的目標及範圍，優先使用指定文件，避免重複建立或改錯對象。

現有流程即使不傳 --submit，也可能建立並寫入自動保存的雲端文件，不能描述為沒有雲端副作用的預覽。--submit 不能當作分享、公開或權限變更的證據。

本地準備、雲端寫入、保存與分享權限分別回報。需要證明保存時重新開啟，核對題目、正文、圖片、表格與保存狀態。回報真實文件網址，網址存在不代表任何人可讀。

新增協作者、開放連結訪問或變更權限須有當次相應授權並核對結果。未確認持久化或未支援內容如實說明。憑證、Cookie 與私人資料不進入規範、來源包或 Git，內容輸入或腳本退出不等於全部完成。

## 確認後的 Skill 工作

現有材料為 w0x7ce-post-to-tencent-docs，目前 CLI 主要接收題目、正文及瀏覽器選項。確認後核對寫入、自動保存與驗收；Markdown 轉換、檔案導入、圖片、表格與其他類型依實際實作逐項驗證，不預先宣稱支援。
