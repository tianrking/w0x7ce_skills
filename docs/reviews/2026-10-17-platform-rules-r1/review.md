# 跨平台內容編輯共用規範

## 適用範圍

適用於不同平台的文章、頁面及其他內容編輯。平台具體格式、長度、素材比例和交付方式由各平台 `rules.md` 定義；不把某一平台的慣例當作所有平台的要求。

## 內容品質

- 使用自然、清楚的繁體中文；其他語言依當次需求。語氣中肯、謙遜、專業，避免說教、浮誇、空泛口號與機械套話。
- 內容完整，標題與實際內容一致。結構、開頭、圖數、配色和敘事方式服務題材，不套用單篇成功案例。
- 核對重要事實、數字、引文和適用範圍；區分來源說法、推論、示意與實際觀察。翻譯尊重原文，不擅自改寫結論。
- 圖片應協助理解，保留必要圖說及來源。生成示意圖不冒充官方截圖或測試證據；不公開憑證、私鑰及不應披露的個人資訊。
- 只宣稱已實際驗證的結果。檔案在本機正常，不等於平台草稿、保存或發布已成功。

## 規範與流程的分工

- `rules.md` 描述使用者希望得到的結果、品質、邊界和驗收條件；可由使用者直接編輯，也可由 AI 按明確指示整理。
- Skill 描述如何完成工作，引用規範而不重複維護完整副本；腳本負責適合自動化的重複處理與檢查。
- AI 可以改善執行方法，但不自行改變人的目標、增加未確認的硬性標準，或刪除已確認要求。
- 當次明確要求優先；平台規範與共用規範衝突時，採用平台明確列出的例外。未解決的實質衝突應說明，不靜默猜測。
- 長期規範、單次需求和 AI 建議分開。沒有使用者確認，不將單次安排或推測升格為通用標準。

## 修訂與交付

- 按授權範圍修訂。只改規範時不重寫已確認作品；局部調整不順便改寫全文。
- 同一作品的多種格式保持內容版本一致。來源、圖片和必要說明可搬移，避免依賴臨時網址或個人電腦路徑。
- 交付格式由平台規範和當次需求決定，不強制所有平台使用微信的按鈕、HTML 或封面形式。
- 維持單一規範來源，版本控制記錄變更；文章歷史、生成快取和發布包不持續載入 Skill 上下文。

# 微信公眾號文章通用標準
寫作、查證、圖文設計、排版與交付

## 適用範圍
本標準用於不同主題的微信公眾號文章，包括科普、技術解說、研究介紹、產品分析、經驗整理、觀點文章與翻譯。它定義共同的品質要求，不規定每篇文章都使用相同的開頭、章節順序、配色、圖數或敘事套路。單篇文章的案例與臨時要求，不自動成為其他文章的規則。

## 一、寫作立場與語氣

使用自然、完整、易讀的繁體中文。語氣中肯、謙遜、專業，尊重讀者的理解能力。

把事情講清楚，讓專業體現在資訊準確、解釋到位與取捨合理。避免居高臨下的說教、誇張宣傳、空泛口號、強行煽情與反覆自我標榜。

直接說明有意義的觀點、行為與結果。少用刻意製造對立的句式、機械轉折或沒有內容的結論。

術語按需要使用，首次出現時提供足夠解釋；不為顯得專業堆疊名詞，也不為通俗而抹去關鍵條件。

描述優點時交代成立條件，討論限制時說明實際影響。比較以證據、用途與取捨為依據，避免為抬高一方貶低另一方。

## 二、選題、標題與導入

先確認文章要回答什麼問題、提供什麼資訊，以及讀者需要哪些背景。每篇文章應有清楚的中心，相關材料圍繞中心展開。

標題準確、簡潔、具體，與正文實際內容一致。可有吸引力，但不製造正文無法支持的承諾。

導入依題材選擇：可以從問題、事實、場景、觀察、研究結果或必要背景切入。選擇能讓讀者最快進入主題的方式。

不預設要求先介紹經典方案、先寫某個品牌、先作對比或先講個人經歷。只有在背景或比較確實幫助理解時才使用。

不預設添加日期、實測標籤或裝飾性背景資訊。若時間、版本或事件背景本身影響理解，則保留並放在合適位置。

## 三、文章結構與敘事

交付完整、連貫、可直接閱讀的文章，不以摘要、提綱或零散問答代替全文。

結構服務內容。可依文章目的採用解釋、分析、敘事、論證、步驟或原文結構，不強制所有文章套同一組章節。

重要資訊應放在讀者容易找到的位置，背景與細節按理解所需逐步補充。不要把工作過程流水帳當成文章主線。

每段發展一個主要意思，段落之間有清楚的邏輯關係。小標幫助閱讀，但不要切得過碎；條列與表格用於真正適合並列或比較的資訊。

例子用來解釋觀點，不能代替論證，也不能把某次案例的條件推廣成普遍結論。例子與實際對象的差異需要時要交代。

結尾可以停在已充分展開的觀點、實際含義或仍待解答的問題，不強加口號式升華或重複前文的總結模板。

## 四、資料、來源與事實邊界

優先使用與主題直接相關、可追溯的原始或權威材料。數字、引文、日期、版本、名稱與重要結論應有依據。

區分來源明確陳述的事實、作者的解釋或推論，以及個別觀察或實測。不要把推論寫成官方結論，把示例寫成真實結果，或把有限驗證寫成全面保證。

只補充有證據支持的內容。材料不足時保留不確定性，不靠想像填補細節。

翻譯與資料整理尊重原文的論點、數字、條件、引用與重要限制；必要的解說應與原文內容區分。

涉及時效性的資訊，核對適用日期或版本。涉及個別測試時，說清楚測試對象、條件與範圍；無需每篇文章都附實測段落。

引用靠近相關內容，讓讀者知道它支持什麼。微信正文保留必要的完整可見網址，避免只有不可辨識的隱藏連結。

公開前移除密碼、金鑰、Token、私人訂閱網址、原始個資與其他不應公開的內容。示例或匿名化處理需保持技術與敘事上的準確性。

## 五、封面與整體視覺

封面、標題、導入與正文應描述同一主題。封面標題可以比正文更短，保留必要關鍵詞，避免堆滿副標、日期與口號。

配色、字體層級與圖形語言在同篇文章內保持協調；不同題材可使用不同風格，不把某一篇文章的色號或插畫形式固定成通用模板。

保持清楚、克制、有留白的呈現，讓視覺幫助理解。封面需在常見顯示尺寸下仍能辨識主題與標題，重要元素留出裁切空間。

每篇文章都必須提供合適的封面圖片。依主題生成新封面，或尋找有明確來源且適合使用的既有圖片；不要只提出封面構想而不交付圖片。選圖或生成時，兼顧主題準確、視覺品質與正文風格；使用外部圖片時保留來源及必要的使用條件說明。

封面作為獨立圖片檔案交付，便於直接上傳平台封面欄。需要不同尺寸時另行輸出，避免拉伸造成失真。

生成圖適合用於插畫或概念表達。不得把生成畫面偽裝成官方截圖、現場照片、產品實際介面或測試證據。

## 六、配圖、圖表與截圖

圖文並茂以增加資訊價值為目的。每張圖應有明確作用，例如呈現對象、解釋關係、比較差異、展示資料或提供原始材料脈絡。

依內容選擇照片、插畫、流程圖、架構圖、數據圖表或截圖。不固定每篇的圖數，也不要求每篇都加入官方截圖。

自製圖解可適度簡化，但方向、比例、標註與條件不能造成誤解。數據圖表需讓數值、單位、範圍與來源可辨識。

需要官方或原始截圖時，直接從真實來源取得，保留足夠脈絡，選擇與正文相關的部分，不重建或偽造原始畫面。

圖說交代圖片在說明什麼；外部材料附來源，並區分原圖、自製示意、官方示例與個別實測。引用材料與本文內容的差別，在必要時說明。

有圖後可以精簡重複的示意框或描述，但保留理解所需的解釋。不要為增加圖片而堆疊相同資訊。

保留可用的原始圖片與適用的可編輯來源，便於平台補圖、修改和再利用。

## 七、微信排版與交付

預設交付完整 HTML 排版頁，供電腦瀏覽器一鍵複製富文字，貼進微信公眾號網頁正文編輯器；不只交原始碼、Markdown 或內容摘要。

正文使用適合微信的內嵌樣式，保持清楚的字級、行高、段距、標題層級與重點提示。避免依賴外部樣式、外部字型或正文腳本效果。

圖片適應正文欄並保留長寬比。長網址、表格或代碼等特殊內容應避免橫向溢出；文章不需要的版面元素不用硬加。

HTML 排版頁必須提供兩個分開的按鈕：

1.「一鍵複製正文」：複製完整正文及配圖，保留適合平台的富文字排版；排除工具列、操作說明與狀態訊息。
2.「一鍵複製題目」：只複製完整文章題目，方便直接貼入平台的標題欄；不帶正文或其他說明。

兩個按鈕都屬必備交付，不能以手動選取、原始碼或檔案下載取代。正文剪貼簿提供富文字與純文字格式；題目使用純文字。另保留瀏覽器權限受限時的合理複製備援方式。

保留圖片原檔，讓平台未接受內嵌圖片時仍可補入。不同平台可能調整部分格式，依實際驗證範圍描述相容性，不保證所有平台完全一致。

主要流程是電腦網頁編輯，不把手機操作設為必經步驟。沒有保存並重新開啟平台草稿時，不宣稱平台端持久化或發布已驗證。

基本交付必須同時包含以下內容：

1. 完整 HTML 排版頁：具備「一鍵複製正文」及「一鍵複製題目」兩個按鈕，可獨立開啟；正文樣式與圖片應隨檔交付，避免依賴臨時預覽服務。
2. 可搬移的 Markdown 來源資料夾：包含完整文章 Markdown、圖片子資料夾與簡短使用說明。正文配圖全部使用相對路徑，例如 images/figure-01.png；不使用本機絕對路徑、臨時網址或內嵌 Base64 取代圖片檔案。引用來源仍可使用正常網頁連結。
3. 可直接使用的獨立封面圖片：依題材生成或尋找適合且可使用的圖片，交付原檔，並一併放入來源資料夾；封面不必重複插入正文。

Markdown 與 HTML 保留相同題目、完整正文、圖說、引用與配圖內容；只允許呈現方式因格式而不同。Markdown 不保證重現微信富文字的所有視覺樣式。

來源資料夾整體搬移後，圖片仍須正常顯示。交付資料夾本身，並提供保留目錄結構的 ZIP，方便下載、保存及轉交。檔名依文章決定，不固化單篇題材；引用或截圖來源記錄、可編輯圖源等，依實際內容補充。

修訂時同步更新兩種文章格式與下載包，避免內容版本不同。後續製作流程宜維持單一正文來源，再產出不同呈現格式。

# X 內容編輯與發布規範草案

本文件待確認，共同品質引用根目錄 shared-rules.md。

## 內容與結構

適用於單則貼文、串文、圖片或影片配文，以及帳號實際支援的長文。按題材選形式，不預設所有主題都做串文。

使用自然、清楚的繁體中文，其他語言依需求。語氣中肯、謙遜、專業，不強制情緒化開頭、Emoji、Hashtag、懸念或互動誘導。

單則有清楚中心；串文按理解順序拆分，標明順序與各則媒體；長文交付完整正文。只在需要標題的形式單獨提供題目。必要背景、條件及來源不能為簡短而失真。

跨平台改編保留原意、證據及限制，再調整節奏與篇幅，不直接截斷原文。數字、引文及重要結論可追溯；來源、推論、示意與實測分開，時效資訊核對日期或版本。

## 素材與交付

配圖有資訊作用，媒體順序與正文一致，不固定張數；標註清楚，重要元素留出裁切空間。需要封面時生成或尋找合適且可使用的圖片，交付原檔；純文字貼文不強制封面。生成圖不冒充官方畫面、照片或驗證證據，外部素材保留來源與必要使用條件。
